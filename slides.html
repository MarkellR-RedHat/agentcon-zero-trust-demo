Chapter 3Theo pokes at it 🤖

With no policy in the way, the agent does whatever it is asked.

No gate

  • The model calls a tool, the tool runs.
  • Reads a protected credential when asked.
  • Sends a config file to an outside address.
  • Runs a command disguised as a diagnostic.

Scoped policy

  • Every call is checked against the task's scope.
  • Protected paths denied, by rule not by content.
  • Egress only to the one allowed host.
  • Only the task's own command is allowed.

Chapter 5The guardrails paradox

Guardrails you don't control can lock the defender out. Scope the ones you do.

July 2026: an autonomous AI agent moved through Hugging Face's dataset pipeline over a weekend, chaining more than 17,000 actions across short-lived sandboxes. When the team started the log analysis, they first used frontier models behind commercial APIs. It did not work, because those requests were blocked by the providers' safety guardrails, which cannot tell an incident responder from an attacker. They ran the forensics on an open-weight model on their own infrastructure and did in hours what would have taken days.

What a content filter costs

22 through, 1 task blocked

The blunt filter guesses from the bytes. It let through the calls that read like ordinary ops work and blocked an honest check. The scoped policy, keyed on the task, let 0 through and blocked no honest work.

Wrap-up

Zero trust for agents is scope plus a trace, not a bigger refusal list.

  1. Grant capability progressively, and red team each grant before the next one.
  2. Scope the policy to the task, so it tells a responder from an attacker by the path, the host and the command, not by how the text reads.
  3. Trace every tool call, because you cannot govern what you cannot see.

🤔 Things to think about

  • Does your agent's policy key on the task, or on the content?
  • Do you have a trace of every tool call it has made?
  • Can your incident responder still work under your guardrail?
  • Who wrote down what the agent is allowed to do?
